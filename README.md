# 鲜智链 FreshChain：多 Agent 编排调度的生鲜智能决策平台

> 2026 第五届未来杯创新大赛 · 初赛作品
> 面向社区生鲜店「消费者买得明白、经营者卖得精准」的双端智能决策平台。

## 一、项目简介

鲜智链（FreshChain）是一个基于大模型 **Agent 工具编排调度** 的生鲜智能决策平台。它不做"套一个大模型聊天框"，而是把重点放在**自研调度、多 Agent 分工、结果交叉核验与 PDCA 自我修正**上：

- **消费者端**：查今日特惠、比价、看库存、挑选储存常识问答（RAG）、购物清单按库内真实单价计价；
- **门店端**：近 7 天热销 / 滞销榜、分档补货建议（多进 / 少进停进 / 维持）、销量条形图、每条建议附置信度。

平台以通义千问 qwen3.7-flash 作为推理核心，采用「Dify 编排外壳 + 自研 Python（FastAPI）调度服务 + MySQL 业务数据」三层架构，实现需求理解 → 任务路由 → 多 Agent 协作 → 结果交叉核验 → PDCA 自我修正 → 反馈记忆优化的全链路闭环。凡涉及数字的部分一律来自数据库，大模型只负责理解意图、组织语言，不参与编造数字。

> ⚠️ **密码与连接配置**：`db.py` 与 `seed_data.py` 的连接参数优先读环境变量（`MYSQL_HOST / MYSQL_PORT / MYSQL_USER / MYSQL_PASSWORD / MYSQL_DATABASE`），未设置时回退到代码内默认值。一键 Docker 复现由 compose 自动注入，无需改代码；本地手动跑请设置环境变量，或把代码里的密码占位 `在这里填你的MySQL密码` 改成本机真实密码，否则会报 `UnicodeEncodeError` / Access denied。代码内不写任何真实密码。

## 二、双端功能

| 角色 | 典型诉求 | 平台能力 |
|---|---|---|
| 消费者 | 查今日特惠、比价、了解库存、学挑选储存 | 商品检索、特惠推送、RAG 常识问答、清单真实计价 |
| 门店管理者 | 看热销 / 滞销榜、判断多进少进、要求建议可信 | 销量统计、趋势分析、规则补货、交叉核验、反馈记忆 |

**典型用例**

- **消费者**：问"今天有什么特惠？"→ 返回当日 5 件特惠（原价 / 特惠价 / 库存 / 选购提示），价格经核验与库内一致；问"西红柿怎么挑、能放多久？"→ 走 RAG 知识库答常识，不调业务工具。
- **门店管理**：问"最近什么好卖，该怎么进货？"→ 先给近 7 天热销榜与滞销榜，再输出分档补货建议；初版误判会被验证层抓出并自动收紧重算，标注每条建议置信度。
- **反馈修正**：店主否决某条补货建议并记录，累计否决 ≥2 次后，系统在后续建议中主动下调该商品推荐强度。

## 三、三层架构

```
┌─────────────────────────────────────────────────────────┐
│  Dify 编排外壳（前端）                                    │
│  主 Agent + 消费者/管理/验证 Agent + RAG 知识库          │
│  Agent 定义 · 提示词管理 · 对话界面 · 可视化编排          │
└───────────────┬─────────────────────────────────────────┘
                │ Function Calling / HTTP 工具调用
┌───────────────▼─────────────────────────────────────────┐
│  自研调度服务层（Python 3.12 + FastAPI + Uvicorn）        │
│  意图路由 → 任务分派 → 执行 → 交叉核验 → PDCA 修正 → 落日志│
└───────────────┬─────────────────────────────────────────┘
                │ SQL
┌───────────────▼─────────────────────────────────────────┐
│  数据层（MySQL 8）：goods / sales_records /              │
│  agent_logs / feedback 四张表 + 模拟销售流水             │
└─────────────────────────────────────────────────────────┘
```

**设计边界**：Dify 只承担 Agent 定义、提示词、对话呈现与可视化编排；**调度引擎、验证逻辑、PDCA 循环、反馈优化全部自研为 Python 服务**，未直接使用 LangChain / Dify 的默认编排流水线，Dify 是可替换的接入外壳。

一次请求的数据流：用户文本 → Dify 主 Agent → 统一编排入口 `/api/orchestrate` → 调度服务完成意图识别、取数、核验、循环 → 返回结构化结果（`answer / confidence / retry_count / trace / latency_ms / chart`）→ 主 Agent 整理为自然语言回复，并在末尾附核验置信度。

## 六、运行步骤

### 快速复现（一键 Docker，推荐）

已内置 20 商品 + 45 天模拟数据，无需手动建库、改密码。装好 Docker Desktop / Docker Compose 后，在项目根目录执行：

```bash
cp .env.example .env        # 一般无需修改，留空使用内置默认值
docker compose up --build   # 起 MySQL8 + FastAPI，自动建库、灌数、启动
```

启动完成后浏览器打开 `http://127.0.0.1:8000/` 即可使用消费者 / 门店门面页，核心调度、交叉核验、PDCA 自动修正、清单计价与销量条形图全部可用。

> 说明：Dify 对话智能层依赖云端模型密钥，完整多 Agent 对话以演示视频为准；本一键包覆盖核心调度与数据功能，无需云端密钥即可复现后端服务与门面界面。

### 本地手动运行（不使用 Docker）

> 以下步骤在项目根目录 `freshchain/` 内执行。

1. **准备数据库**：启动 MySQL，执行建表脚本：

   ```bash
   mysql -u root -p < freshchain_schema.sql
   ```

2. **安装 Python 依赖**：

   ```bash
   pip install fastapi uvicorn pymysql pydantic
   ```

3. **配置连接**：设置环境变量 `MYSQL_HOST / MYSQL_PORT / MYSQL_USER / MYSQL_PASSWORD / MYSQL_DATABASE`（推荐），或把 `db.py` 与 `seed_data.py` 里的密码占位改成本机真实 MySQL 密码。

4. **灌入模拟数据**（20 种商品 + 45 天流水，固定随机种子可复现）：

   ```bash
   python seed_data.py
   ```

5. **启动 FastAPI 服务**：

   ```bash
   uvicorn main:app --host 0.0.0.0 --port 8000 --reload
   ```

   - 浏览器打开 `http://127.0.0.1:8000/` 可直接使用静态门面页；
   - Swagger 文档：`http://127.0.0.1:8000/docs`。

6. **接入 Dify（可选，用于完整演示）**：

   - 在 Dify 中导入本服务的 OpenAPI Schema（`/openapi.json`），把工具挂给主 Agent；
   - 容器内访问宿主机服务使用 `http://host.docker.internal:8000`（代码已在 `servers` 中声明，并开启 CORS）；
   - 新建知识库并挂载 `knowledge.md`，用于"怎么挑、怎么存"类常识问答。

7. **校验数据**：建表灌数后可运行 `verify_check.sql` 逐条核对商品数、特惠、热销 / 滞销榜。

## 七、接口清单（main.py）

| 接口 | 方法 | 作用 |
|---|---|---|
| `/api/goods` | GET | 商品列表（分类 / 关键词筛选） |
| `/api/promo` | GET | 今日特惠商品 |
| `/api/goods/{goods_id}` | GET | 单个商品详情 |
| `/api/sales/top` | GET | 近 N 天热销榜（默认 7 天，可传 days / limit） |
| `/api/sales/slow` | GET | 近 N 天滞销榜 |
| `/api/restock/suggest` | GET | 规则型补货建议（日均销量 / 可售天数 / 趋势 / 置信度） |
| `/api/verify/consistency` | POST | 价格 / 库存一致性核验，返回通过项与置信度 |
| `/api/orchestrate` | POST | **统一编排入口**：意图识别 → 分派 → 执行 → 核验 → PDCA 循环 |
| `/api/feedback` | POST | 记录采纳（adopted=1）/ 否决（adopted=0）反馈 |

## 八、关键设计

- **自研意图路由**：管理类词（销量、好卖、滞销、进货、补货、榜单、趋势…）与消费类词（特价、特惠、多少钱、怎么挑…）分别统计命中数，管理类优先级更高，避免"我要进货买鸡蛋"被误判；未命中默认消费者任务。
- **交叉核验（有效售价口径）**：声称价必须等于库内"有效售价"——当日特惠品比 `promo_price`、普通品比正常价；库存逐项比对；置信度 = 通过项数 / 检查项总数，低于阈值触发修正。开发中曾因只比正常价导致正确特惠价被误判，后改为有效售价口径。
- **PDCA 自循环**：Plan 路由分派 → Do 产出初版 → Check 验证给置信度 → Act 未通过收紧规则重算，最多 3 轮；达上限降级为保守建议并在日志标 `degraded`，不无限重试。演示模式用宽松初版（日均 ≥20 即多进），现场展示"发现误判 → 自动修正"。
- **反馈记忆闭环**：采纳 / 否决写入 `feedback` 表；同一商品否决累计 ≥2 次，从"多进"下调为"维持"，理由注明历史否决次数。
- **购物清单真实计价**：从问句解析商品与数量（支持中文数字"三斤 / 四个"），按库内有效单价逐项小计并合计，价格不经过模型估算。
- **门店条形图**：`/api/orchestrate` 返回 `chart`（热销 top5 / 滞销），前端 `index.html` 用纯 HTML/CSS 渲染绿色热销条、橙色滞销条。
- **埋点**：`agent_logs` 记录 `confidence / retry_count / latency_ms / status`，为决赛并发调度数、平均延迟、任务成功率对比提供数据。
